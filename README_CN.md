## 🧠 为什么做 Otta？

AI 很强，但现实很复杂：

- Token 消耗不可控，越用越焦虑
- 每次都要写提示词、调模型
- 插件繁杂，流程混乱
- 数据上传云端，隐私不透明
- 对话是一次性的，没有积累

Otta 的目标很简单：

> 让 AI 成为一个可长期依赖的工具，而不是一个成本黑洞。

# ✨ 核心能力

## 💰 少烧钱

### 1️⃣ 结构化输出引擎

- JSON 输出 + 模板渲染
- 避免无效 token 消耗
- 同等质量下成本降低 60–70%

### 2️⃣ Golden Replay（智能回放）

- 重复任务复用历史最佳执行路径
- 成功方案直接重放
- 大幅减少 LLM 调用

### 3️⃣ 成本可视化

- 每日 token 消耗图表
- 搜索 API 用量统计
- 成本透明可控

## 🧠 智能核心

四大核心引擎协同驱动，让 Otta 越用越聪明。

### 🎯 意图引擎（Intent Engine）

- 自动识别用户意图，选择最合适的工具集
- 基于历史 Case 复用执行计划，减少 LLM 调用
- 路由置信度实时可见

### 🧠 策略中枢（Strategy Hub）

- 沉淀高频任务为 Golden 模板和实例
- 结构化回放：相同任务零 LLM 成本完成
- 候选方案自动提炼，模板生命周期管理

### 💎 执行棱镜（Execution Prism）

- 每日执行质量分析：成功率、步数、工具调用
- 错误趋势追踪，自动发现瓶颈
- Golden 候选自动发现，驱动策略沉淀

### 🌲 能力森林（Capability Forest）

- 根据日常任务自动推荐新能力（MCP / Skills / 内置）
- 试用机制：7 天观察窗口，通过标准自动转正
- 30 天未使用自动休眠，保持路由空间清爽
- 不自动安装，启用必须确认，全程可解释

> 从 2~3 个能力自然增长到 20~30 个，且全程可控。

## 🛡️ 放心用

安全是第一设计原则。

- 默认本地数据处理
- 文件操作必须确认
- 危险操作直接拒绝
- 全系统零永久删除
- 删除统一移至回收站，可恢复

你不需要担心：

- 误删文件
- 数据外传
- AI 乱执行
